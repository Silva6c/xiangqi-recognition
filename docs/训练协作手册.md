# 训练协作手册（多 agent 协作协议 v2）

> **给任何接手训练工作的 agent**：本文=协议+模板库。你不需要历史会话记忆。
> **必读只有 §0（30 行路由表）**，其余按路由跳转——省 token 是硬约束，禁止无路由通读。
> 配套：`docs/训练工作台账.md`（活跃状态，<80 行）+ `judges/*.json`（判据源）+ 根 `AGENTS.md`（冷启动协议）。

## §0 路由器（必读）

### §0.1 我是谁 / 我要干嘛 → 去哪

| 你的处境 | 去哪 | 干什么 |
|---|---|---|
| 新会话接手（任何角色） | → §0.2 冷启动五步 | 5 分钟定位到"现在该干嘛" |
| 要点火训练 | → §3 卡模板 A | 三查→填卡→执行（**先确认用户说过"点火"**） |
| 要验收一轮训练 | → 一条命令见下 | `python corner_accept.py --pt runs/<名>/best.pt`，读末行 VERDICT |
| 要出部署权重 | → §3 卡模板 C | 本仓只产 onnx+契约，APK 由接入方仓构建 |
| 出事故了 | → §3 卡模板 D | 保现场→复现→归因→回退 |
| 被派来当评测工（子代理） | → §5 | 按模板执行，只跑评测命令 |
| 要立新版本（v68…） | → §6 维护协议 | 复制模板填空，禁止重新设计 |

### §0.2 冷启动五步（任何 agent 开工固定动作）

1. 读 `docs/训练工作台账.md`（<80 行）：**焦点 → 运行中 → 任务卡 → 等用户**。
2. 找到属于自己的任务卡（角色匹配）；**没有卡=不要自作主张开工**，在"等用户"区留言或等总控建卡。
3. 核对 §1 铁律（内存三查口令在 §1.1，违反=搞崩用户机器）。
4. 按卡上"动作"字段执行（命令原样复制，只换 `<变量>`）。
5. 干完：更新卡状态 → 更新台账"焦点" → git 提交。**收工必更台账。**

### §0.3 文件分工（哪个状态写在哪）

| 信息 | 写哪 | 生命周期 |
|---|---|---|
| 轮内活跃状态（跑着什么/下一步） | 训练工作台账.md | 轮内，done 即删（git 历史即归档） |
| 轮末结论（判决数字/教训） | 方案文档回填 + 对应 vXX judges JSON | 永久 |
| 判据 | judges/*.json（**唯一可信源**） | 永久，禁改已注册项 |
| 评测原始输出 | data/reports/ | 不入 git，关键数字抄进 docs |

## §1 铁律（违反=搞崩机器/口径作废，无例外）

### §1.1 内存纪律（本机 32GB，两次实爆入档）

1. **起重进程前三查**（一条条跑）：
   ```bash
   tasklist //FI "IMAGENAME eq python.exe"
   powershell -NoProfile -Command '[math]::Round((Get-CimInstance Win32_OperatingSystem).FreePhysicalMemory/1MB, 1)'
   ```
   残留≠0 先清理；空闲 **<10GB 不启动**；第三查=心里报峰值预估。
2. **任何时刻一个重进程**。重量级：corner 训练 ~6GB / r3 训练 ~25GB+ / gradle ~30GB / 大评测。
   轻量（评测五连、读 npz、单帧推理）不占重进程名额。
3. **长跑一律 run_in_background**（前台 cancel 不杀子进程=孤儿吃内存到爆）。
   停任务后必须 `tasklist` 复查无 python 残留。
4. **gradle 与训练互斥**；训练资源分级（用户拍板 2026-10-27）：
   **corner 系资源拉满安全**（占用少：batch 256×workers 16 实测水位 <8GB），
   **其他线（r3 系）禁止拉满**——r3 batch96 内存墙 58.8GB 被保命终止实锤（v66），
   r3 系锁死 preset 的 batch 48。
5. 磁盘 I/O 100% = 内存换页症状，先查内存再查磁盘。

### §1.2 红线

1. **评测集永不入训**：eval_* npz、GEN_HOLDOUT 字体、各池 `split=="holdout"` 帧、
   screen30_v1（seed 20261025）、`corner_qq_basis.npz`（QQ 基准）。
2. **训练点火权在用户**（用户明说"开始/点火/重训"才起训练进程）。
3. `data/`、`runs/`、`fonts/` 不入 git；**评测数字必须抄进 docs 留存**。
4. 外部数据集仅训练自用、不分发、记录出处；对话/注释/文档一律简体中文。
5. `cudnn.benchmark` 永禁；工作目录一律**本仓库根**（脚本平铺根目录，import 同目录）。

## §2 角色与权力

| 角色 | 权力 | 禁止 |
|---|---|---|
| 总控（主会话） | 点火执行、判 PASS/FAIL、建卡/删卡、改方案 | 绕过判据宣布通过 |
| 评测工（子代理） | 跑评测命令、写报告文件 | 点火训练、gradle、改代码/判据 |
| 目检工（子代理） | 读 PNG 出 PASS/FAIL 一行结论 | 改任何文件 |
| 构建工 | （分家后本仓无 gradle 构建单元；接入方仓构建时）互斥窗口 | 训练运行中构建 |
| 文档工 | 登记/整理 docs | 改判据、改台账历史 |

## §3 任务卡模板库（填空即用，禁止自由发挥格式）

> 台账里的每张卡按此模板。字段语义：**动作=可直接执行的命令**；**判定=引用判据 id
> 或明确完成条件**；**下一手=完成后触发什么**（消除"然后呢"）。

### 模板 A：corner 训练轮

```markdown
### [T<n>] corner <版本名> 训练 {状态: todo|doing|blocked|done}
- 角色: 总控
- 前置: 用户已说点火；内存三查过；runs/<版本名>/ 不存在
- 动作:
  1. 冒烟: python corner_train.py --run-name <名>_smoke --steps 300   # ~11min，loss 降+val 行正常=通
  2. 正式（**拉满档，默认**）: python corner_train.py --run-name <名> --steps 600 --batch 256 \
       --lr 5e-3 --workers 16 --real-npz data/pools/corner_v5_pool.npz --val-every 100
     # run_in_background，~25min；等效换算 batch256×600 ≈ 96×1500 ≈ 32×4000（同样本量）
     # 调 batch 时步数等比反调、lr 按 sqrt 缩放；workers=本机逻辑核-4
  3. 监控: tail -5 runs/<名>/log.txt（val mean_px 渲染域正常 <4px）
- 判定: 训练完整跑完（[done] 行落盘）
- 产物: runs/<名>/best.pt + log.txt
- 下一手: → 模板 B 验收卡
- 备注: **--real-npz 忘带=真实域零泛化（v67 首轮 0% 判废教训）**；真实池 1285 帧
  入训+平行四边形闸剔 ~27% 属预期
```

### 模板 B：corner 验收轮

```markdown
### [T<n>] corner <版本名> 验收 {状态: todo}
- 角色: 总控（可派评测工子代理执行，判定权在总控）
- 动作: python corner_accept.py --pt runs/<名>/best.pt --judges judges/<版本>.json
  （耗时 ~8min，逐项 PASS/FAIL 一行 + 末行 VERDICT；报告落 data/reports/<名>_accept.json）
- 判定: VERDICT 行 + judges/<版本>.json（唯一可信源，文档表格只是引用）
- 产物: data/reports/<名>_accept.json；**VERDICT 行原文抄进台账"判据快照"区**
- 下一手: PASS → 模板 C；FAIL → 台账归因（哪个判据、什么形态）→ 修正方案 → 等用户拍板
- 备注: 单项重跑用 --only qq,screen30；判据 JSON 严禁改
```

### 模板 C：导出与构建部署

```markdown
### [T<n>] corner <版本名> 导出部署 {状态: todo}
- 角色: 总控（构建可派构建工，须训练/评测全停）
- 动作:
  1. 导出: python corner_export.py --ckpt runs/<名>/best.pt --out runs/<名>
     （判读: torch/onnx 对拍 max|Δ|<1e-4；输出名 ["simcc_x","simcc_y"]，每头形状按版本契约见下方雷区注）
  2. 对拍: python qq_basis_check.py runs/<名>/corner_simcc_fp32.onnx   # onnx 后端同判
  3. 发布: 新 onnx → weights/corner_simcc_v1.onnx，同步更新 weights/README.md
     的 md5/契约行；本仓 android/ 为参考实现（无构建单元），接入方（App 项目）
     按接入方自身的 assets 与解码代码做**原子替换**（模型与解码成对上线）
     【雷区】文件名 v1 是坑位名非版本名；v64 [1,4,512] 与 v67 [1,3,512] 与
     v68 [1,7,512] 输出形状互不兼容，换权重必须连同接入方解码代码一起换
  4. 单测: python tests/test_corner_model.py（6 项秒级：契约/往返/限幅/体积预算）
- 判定: 对拍 <1e-4 + 测试全绿 + weights/README 已更新
- 产物: weights/ 新 onnx + 契约文档
- 下一手: 台账收官（判据快照+下一手卡）→ git 提交；接入方（产品 App）由
  其自身仓库同步（两仓同步义务见 README「两仓关系」）
```

### 模板 D：事故诊断

```markdown
### [T<n>] 事故: <一句话现象> {状态: doing}
- 角色: 总控
- 动作:
  1. 保现场: 手机日志（adb logcat）+ PC 服务日志 + 出事截图，存 .cache/
  2. 桌面复现: 模板=.cache/diag_incident.py（QQ 象棋事故逐层对拍：截图→角点 A/B
     →warp→r3/级联→与目检真值逐格分歧）
  3. 归因分层: 定位层（角点偏/塌缩/护栏拒绝）→ warp → 识别（r3/级联）→ 结构闸
  4. 回退: weights/ 换回上一代权重+更新 README md5（分钟级止血，v4/v6 前科：回退优先于带伤修复）
- 判定: 根因写入台账（证据链 ≥2 条）；回退属部署动作须告知用户
- 下一手: 修复方案文档 → 等用户拍板
```

## §4 判据体系

- **唯一可信源**：`judges/corner_v67.json`（7 规则，J7 为真机观测项）。
  手册/方案文档里的判据表格只是引用，**冲突时以 JSON 为准**。
- **执行**：`corner_accept.py` 自动对表（subprocess 跑评测+解析+判定+落报告）。
- **改动纪律**：已注册规则禁止修改/删除；新版本立项时复制 JSON 改名（corner_v68.json）
  追加规则；判线调整=新一轮=需用户确认。

## §5 子代理调用规范（总控读）

**派发原则**：评测五连/目检/文档整理→派；点火训练/判决/gradle→总控亲自。

### 评测工 prompt 模板（Agent tool，subagent_type=general-purpose）

```
你是评测工。工作目录=本仓库根（xiangqi-recognition）。
必读（只读这三样，禁止通读其他文档）：
  1. docs/训练协作手册.md 的 §1 铁律、§5 本节
  2. docs/训练工作台账.md 的"任务卡"区里指派给你的卡

任务：执行卡 [<id>] 的"动作"字段命令，逐条跑完（轻进程可顺序执行）。
把每条命令的输出末尾 10 行 + VERDICT 行写成 MD 报告，存到
data/reports/<名>_验收.md，
返回消息只给：各判据 [PASS/FAIL] + 数值 + VERDICT 原文（≤10 行）。

边界：只许跑卡上列出的评测命令；禁止起训练进程、禁止 gradle、禁止改代码/判据/台账。
```

### 目检工 prompt 模板

```
你是目检工。用 Read 工具逐张查看以下 PNG：
<路径列表>
对每张图只回答一个问题：<具体核验问题>。
```

### 结果处置

子代理返回 ≠ 采信：总控核对报告文件里的原始数值；判据判定以 judges JSON 为准；
关键结论由总控抄进台账（.cache 不入 git）。

## §6 维护协议（可持续性的关键：谁在何时更新什么）

| 事件 | 必须动作 | 更新哪 |
|---|---|---|
| 点火训练 | 台账"运行中"加一行（任务id/命令/日志路径） | 台账 |
| 训练完成 | 删"运行中"行 → 建验收卡 | 台账 |
| 验收出 VERDICT | VERDICT 原文贴"判据快照"区 → 建下一手卡 | 台账 |
| 判决 PASS/FAIL | 结论+数字回填方案文档 → 台账判据快照保留原文 | 方案文档+台账 |
| 收工（每轮） | 台账 <80 行检查 → git 提交（台账必须进 commit） | git |
| 立新版本 | 复制 judges JSON + 模板卡填空 | judges/ + 台账 |
| 新增文件 | 登记进 docs/README.md 地图 | docs/README.md |

**台账反膨胀规则**：done 的卡立即删除（git 历史即归档）；历史数字进方案文档；
台账任何时刻 <80 行，超了=有人违约。
