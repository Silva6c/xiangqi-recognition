# 自研识别引擎一期评测报告（阶段 0~2）

> 日期：2026-10-04 ｜ 方针：docs/自研识别引擎方针.md ｜ 基线：《识别引擎性能对比实验报告》
> 产物：`phone/tools/recog/`（渲染器/训练/导出/评测全链路）+ `runs/v1,v2` 模型

## 一、结论先行

1. **工程链路全部打通，速度/体积/算子门槛大幅超标达成**：自研 grid-head 模型 int8 **0.70MB**（现役 Swin 10.35MB 的 7%），桌面 CPU 单帧 **1.4ms**（同口径现役 151ms 的 **1/108**）；算子集纯净（Conv/MatMul/Relu 等 6 种 + QDQ 标准算子），ir_version=8 兼容 ORT-android 1.17.1。
2. **准确率门槛未达成，根因已定位到「必须上真实数据」**：bench 真实帧（10 局三源交叉真值）上 occ 仅 52.7%（现役 99.7%）。经三层诊断：①姿态尺度错配（RTMPose 把 cnvcs 外框当网格角，最优校正 scale 0.91~0.94）；②**外观域差是主瓶颈——几何校正到最优后 occ 上限也只有 69%**。纯合成路线已到顶，续命只能靠真实帧回流训练。
3. **数据飞轮被环境阻塞**：模拟器存在僵死 qemu 进程（PID 11636，taskkill/Stop-Process 均无法结束，只读并发实例也被其锁拒绝），真实帧采集无法进行。需人工结束该进程或重启机器后继续。

## 四、根因链（bench 失败的三层诊断）

1. **差分标注链验证 90/90 通过** → 合成数据内部自洽，排除标注 bug。
2. **v1 混淆模式**：空格↔邻格棋子互换（错位指纹）+ p↔P 色彩翻转。
3. **象限偏移测量**（矛盾）→ **采样网格叠加目检**：窗口与棋子错位约半格、方向随位置变化 → 不是平移。
4. **网格搜索校正**（以模型精度为目标函数）：最优 scale **0.91~0.94**（低于 v2 增广下限 0.94）→ 实锤 RTMPose 在 cnvcs 上把**外框**当网格角（warp 后网格被放大）。
5. **校正到最优后 occ 上限 69%** → 外观域差独立存在且为主瓶颈：cnvcs 的奶油大盘面/粗楷体/ rim 阴影与合成风格仍有本质差距。
6. **混淆结构**（294 占子格）：漏检 23.8%（集中在边缘格=尺度错配指纹）+ 同形异色 10.2% + 异形混淆 13.3%（错位读邻格所致）。

## 五、下一步（按优先级）

1. **解除模拟器阻塞（需人工）**：结束僵死 qemu（PID 11636，`D:\Android\Sdk\emulator\qemu\windows-x86_64\qemu-system-x86_64.exe`）或重启机器；确认 `adb devices` 无 offline 项。
2. **真实帧数据飞轮（方针既定路径，本报告唯一被阻塞项）**：
   - 启动模拟器 → cnvcs 打谱模式逐着手动翻页，每页 `adb exec-out screencap` 采一帧（目标 50~150 帧多局面）；
   - nano_v3 自动标注（pose→warp→分类，avg logit 置信过滤）——bench 已证其在 cnvcs 上 99.7% 准确，作训练标签足够；
   - v3 训练：真实帧 ~20% + 合成 ~80% 混合，尺度增广下探到 0.85；
   - 预期：bench occ 应一步跨到 95%+（真实分布直接进训练集），bench 100% 门槛随即进入射程。
3. **v3 达标后**：执行阶段 3（端上接入：AssistConfig A/B 开关 → 模拟器全链路 E2E → bench 在机复测 → 真机复验）。
4. 弃权阈值在 v3 后按新 logit 尺度重新标定（ROC 数据管线已就绪）。
