# 自研识别引擎方针（一期：分类模型替换）

> 批准日期：2026-10-03 ｜ 性质：研发方针与执行计划（已批准版 v3）
> 两份输入：《yolo-识别管线研究报告》（上游摸底）、《识别引擎性能对比实验报告》（量化基线）

## 〇、一句话

自己造一个又小又快的「棋子识别」模型，替换现有第三方 Swin 分类模型；数据全自动生成、零人工标注；用 bench 同口径证明「不比现役差」，用渲染器泛化集证明「比现役更普适」。

## 一、背景与两份输入的结论

### 1.1 上游摸底（yolo-识别管线研究报告）

三个上游全部不可作为训练资产来源：

| 仓库 | 许可证 | 训练侧 | 结论 |
|---|---|---|---|
| Vincentzyx/VinXiangQi（YOLO） | GPL-3.0 | 无（纯部署源码） | 不抄代码，模型当黑盒回退 |
| Shirakawa-Kotone/chinese-chess-helper（ONNX） | 无 LICENSE（移植已获作者许可） | 无（纯部署仓库） | 现有移植合法保留；新代码不得抄 |
| TheOne1006/chinese-chess-recognition（训练侧真身） | 无 LICENSE | MMPose+MMPretrain、PNG 贴图增强 | 只借鉴思路（合成数据/指标/失败清单），不碰代码与 demo 数据集 |

其失败实验清单为我们免费探了路：OCR 不行、YOLO 要海量数据、直线检测被压线棋子干扰、端到端标注拿不到——印证「两步式 + 合成数据」选型。其已知弱点（倾斜掉点、黑车/黑卒易混、样式多样性不足）列为我方评测必测项。

### 1.2 量化基线（识别引擎性能对比实验报告）

- **clsRun 占整帧 91%（均值 135ms）**——一期只换分类层即打主力成本；角点部分（~5ms）收益不足 5%，不动。
- **失败哲学**：ONNX「不确定就闭嘴」（318 次快速拒绝零污染）vs YOLO「自信地错」（4 帧结构合法错误局面）——自研模型必须继承 ONNX 的失败模式：逐格置信度 + 整盘弃权。
- **bench_recog 回归基建**（analyze.py / stats.py / cases.json + 12 张三源交叉底片）直接复用为自研模型的同口径跑分基准。
- 资源差距：PSS +94MB、冷启动 +0.75s、APK +30MB——自研小模型三项全收。
- 注意：模拟器上「角点缓存不省时间」不能外推真机（真机 pose 是大头），一期保留 pose 缓存机制不动。

## 二、目标与边界

**一期做**：自研 grid-head 分类模型替换 `nano_v3-0319.onnx`（10.35MB Swin），drop-in 对齐现有契约；RTMPose 角点层、BoardTracker 确认链、YOLO 全部不动。

**一期不做**（二期另立项）：自研角点模型、光流跟踪、走子对齐、摘除 YOLO（摘除时机=新引擎具备可靠拒绝机制之后）。

### 2.1 管线契约（已逐项核实）

| 项 | 契约 | 出处 |
|---|---|---|
| 输入 | `[1,3,315,280]`，warp 450×500 → 中心裁 400×450 → resize 280×315 → ImageNet RGB 归一化 | OnnxGeom.kt:241-252 |
| 输出 | flat 1440 = 90格×16类，行主序，类序 `'.','x','K','A','B','N','R','C','P','k','a','b','n','r','c','p'`，argmax 无 softmax | OnnxGeom.kt:18,292-308 |
| 运行时 | onnxruntime-android 1.17.1；ir_version 需压回；无 ConvInteger → 静态量化 QDQ+校准 | quantize_models.py:46-49 |

### 2.2 验收门槛（双轨 + 资源三项，模拟器口径）

| 维度 | 门槛 | 对标 |
|---|---|---|
| bench 同口径回归（12 局面） | 稳态帧准确率 **100%**，零「合法错误局面」 | ONNX 100% / YOLO 98.8% |
| 渲染器泛化集（≥300 帧） | full-err-0 ≥90%（目标 ≥97%）、格子准确率 ≥99.5% | 上游训练侧 0.83 |
| 拒绝机制 | 非棋盘/低置信画面可靠拒绝，结果流零污染 | ONNX 318 次 null 零污染 |
| 模型推理耗时 | ≤30ms（冲刺 ~10ms） | clsRun 135ms |
| 全帧 P50 | ≤60ms（冲刺 ~30ms；含 warp/pose ~20ms 固定成本） | ONNX 122ms / YOLO 75ms |
| int8 体积 | ≤3MB | Swin 10.35MB |
| 同局面 PSS | ≤300MB | ONNX 361 / YOLO 267 |
| 冷启动加载 | ≤300ms | ONNX 780ms |
| x86_64 开 XNNPACK | 不崩（进程存活） | 上游模型必崩 |

不达标回渲染器补数据迭代，门槛不降；一期失败不伤现有管线（旧模型原样保留）。
