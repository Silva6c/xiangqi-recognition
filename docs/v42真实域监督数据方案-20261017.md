# v42 真实域监督数据方案（2026-10-17）

> 定位：实物照片域 8 倍差距（24 错 vs nano 3 错）的正面强攻方案。三路线侦察定稿 + 数据管线设计。
> 侦察产物：TTA 共识证伪（.cache/tta_consensus.py）、语料盘点、Explore 子代理工程侦察（roboflow COCO 标注复核）。

## 一、三路线侦察结论

### 1.1 TTA 共识自标注——❌ 证伪出局

5 模型（v41/v40/v39/v38a + nano）× 8 TTA 视图 = 40 票逐格共识，26 帧金标准实测：

| 标注方式 | 总错 | 实物域 | App 域 |
|---|---|---|---|
| nano 单标（现状老师） | 19 | 3 | 16 |
| v41 单标 | 42 | 24 | 18 |
| **40 票共识** | **34** | **15** | **19** |

集成确实比单个学生好（42→34），但远不及老师。**机理：学生的错误是相关的**——同门师兄弟共享同样的训练数据偏差，4:1 票数结构下系统性盲区淹没老师的正确判断；分歧格（<70% 共识）对 nano 错误格的覆盖率仅 0.05，连人工仲裁都没有抓手。**无监督共识突破不了蒸馏天花板**——此路正式关闭（负结果与原型 .cache/consensus_proto.npz 留档）。

### 1.2 roboflow COCO 标注——💎 金矿（主攻依据）

此前判定"17330 张整图标注缺失"是**口径误判**：标注以 COCO json（`_annotations.coco.json`）与图片同目录存在。xiangqi-super-dataset train 实测 4107 图 / 33689 框 / 16 类完整类别名（均值 ~8.2 框/图）。

**这意味着约 14 万个真实棋子框带人工类别标注，完全独立于 nano**——棋子框中心 → 格位置、COCO 类别 → 16 类，可直接产出"真实域监督帧"。这是唯一不经过老师手的真监督信号，蒸馏天花板被从根上绕开。

### 1.3 实物棋子移植扩展——✅ 辅助（并行）

augment_real_transplant.py 机制现成（QC = teacher conf ≥0.55 + argmax 双校验；贴片 52×52 圆形羽化 σ1.5）。bench 10 帧历史产出 7901 样本（99.7% 通过、违规 0）；**26 帧人工真值尚未挖掘**，预计 ~2 万样本。改造点：TRANSPLANTS 硬编码组合表泛化（~50-100 行）+ -100 遮挡格语义分支。1 天内量级。

### 1.4 自监督预训练——✅ 可行，降级为补充

36000 对齐真实帧（real_frames_*/real_photo_* 系）可直接做格掩码重建（零对齐成本）；pose_corner 角点 4-5ms/帧（1.8 万整图分钟级）；格 token 暴露 + 重建头 ~100-200 行。有 1.2 的真监督金矿后，自监督降为补充杠杆（v43 候选）。

## 二、v42 数据管线设计（主攻）

### 2.1 管线流程（parse_roboflow_coco.py）

```
COCO json（images/annotations/categories）
→ ①categories 实测映射表 → 项目 16 类（.xKABNRCPkabnrcp）
→ ②每图：RTMPose 角点（pose_corner.detect，4-5ms）→ 失败跳过
→ ③warp 到 450×500 → 裁 400×450 → 缩 280×315（端上同款链）
→ ④棋子框中心按单应映射 → 最近格点（距离 < 半格距阈值，否则丢弃该框）
→ ⑤结构校验（双帅各一/子数上限/总数 ≤32）——失败帧丢弃
→ ⑥产出 real_roboflow_sup.npz（imgs [N,315,280,3] u8 + labels [N,90] + src 标记）
```

### 2.2 质量门（全过才入池）

1. 角点检测成功（boxPlausible 校验过）
2. 框→格映射：框中心距最近格点 < 0.5 × 格距
3. 同格冲突：两框映射到同格 → 保留置信度高者（COCO 无 score 时按框面积），冲突帧降级跳过
4. 结构校验：帅/将各恰 1、子型上限（兵卒 5 余 2）、总数 ≤32
5. 类别映射无歧义（①步确定后固化）

### 2.3 管线实测（已跑通）

- **两套英文命名并存**：general/advisor/chariot/elephant/horse 系与 king/bishop/knight/rook 系——首跑只映射了一套导致 59% 图"框不足"，补齐同义词归并（rook=chariot、bishop=elephant、knight=horse，映射无冲突）后入池翻倍
- **结构校验踩坑复刻**：cnt 口径 v>=0 把空格计入导致总数恒 90——v37 时代 audit_labels.py 同款坑，已修（v>0 只数占子格）
- **RTMPose 一致性偏移**：框-格偏移为随机散布（σ≈10-13px，均值≈0），平移校正无效已留档；质量门正确过滤低质帧
- **最终产出：real_roboflow_sup.npz 2319 帧（585MB）**，入池分布 chess-3j3vb 240 / scan-xiangqi 946 / 其他 933；帅/将每帧各 1、兵卒 6.9k、其余每类 ~2.2-3.1k
- **解锁未竟**：越南语系 3 项目（chess-abplc 673 图 22.9 框/图最大头）因 tuong/tuongx 语义互换历史坑跳过，核验后可再解锁 ~1.5 万框；结构不合法 4563 张（26%）为真噪声帧（摆拍未完成/子数残缺），质量门正常工作
- 目检：入池帧为真实木盘/木刻/人手/杂光照片（.cache/roboflow_sup_sheet.png），正是实物域缺口需要的成像条件；已知局限=COCO 无遮挡语义（被手挡的子标空格），靠结构校验+量级稀释兜底

### 2.4 配套：实物移植扩展（transplant_human26.py）

- augment_real_transplant.py 泛化：TRANSPLANTS 组合表 → 全类×全空位、补 -100 格分支
- 源 = 26 帧人工真值（17 实物帧的实物棋子）→ 预计 ~2 万样本
- 产物 real_human26_transplant.npz

**根因实锤（.cache/roboflow_sup_grid_check.png 网格叠加目检）**：这批照片是**人摆拍展示**——
棋子大半悬在格间空地甚至盘外，COCO 框中心→最近格的几何映射系统性产生错位标签（离格 30px
的车硬贴最近格）；COCO 漏标/chess 类排除的子躺在格上 → 有子标空。双毒并用：位置-类别绑定
污染 + 漏检/幻觉喂养。**教训升级（wave2 的深层版）：真实域数据的门槛不是"图像真实"，而是
"图像内容与标签的几何一致性"**——26 帧人工真值是金标准，正因为标注者按"最近交叉点"人眼判定。

**路线修正**：
1. roboflow_sup 整帧入训 → **废弃**（若要救活需新质检门：框中心距格心 <12px 的严格子集）
2. **实物贴片路线升华为主攻**：roboflow_sup 2319 帧 × ~20 子 × QC ≈ **3 万实物棋子贴片**
   （贴片自带 COCO 类别，位置语义由渲染端标准格位保证——几何一致性天然成立），
   与 26 帧/bench 贴片合流 = v43 弹药
3. **v41 仍是现役最优与部署候选**（四轴全面反超 + 真实域 42/39 + bench 8/10）
